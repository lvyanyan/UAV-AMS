## 1. 系统概述

### 1.1 核心设计原则

| 原则 | 说明 |
|------|------|
| **★ 永久与时效分离** | 永久空域/航路通过 `/api/airspace/data` 一次性加载；时效性空域/航路/气象/飞行计划/告警按 1 分钟包下发 |
| **★ 告警独立解耦** | 告警是独立的时间段实体（与飞行计划同级），不再嵌入帧数据中。支持单无人机多告警并存、时间跳转 diff |
| **★ 飞行计划独立** | 飞行计划是独立实体，不依附于无人机元数据；一架无人机可在回放窗口内执行多次任务 |
| **包分片模式** | 1 小时回放数据等分为 60 个包（每包 1 分钟），通过 `GET /api/drone/packet/{0~59}` 按序号请求 |
| **数据自发现** | 前端从首批 packet 数据中自动发现所有 `device_sn` → 建立 Billboard 槽位映射 |

### 1.2 坐标与单位约定

| 项目 | 约定 |
|------|------|
| **坐标系** | WGS-84 (EPSG:4326) |
| **经纬度** | 浮点数，单位：度（°） |
| **高度** | 浮点数，单位：米（m），海拔高度 |
| **时间戳** | `timems`：整数，**Unix 毫秒时间戳** |
| **速度** | 浮点数，单位：米/秒（m/s） |

## 4. 接口 ②：核心接口 `GET /api/drone/packet/:idx`

### ★ V6 核心变更

```
V5:  data_list = [{ frame: {...}, alarm: {...}|null }, ...]   ← 告警嵌入帧
V6:  data_list = [{ device_sn: "...", longitude: ..., ... }, ...]  ← 纯轨迹帧
     alarms    = [{ alarmId, droneId, alarmType, startTime, endTime, ... }]  ← ★ 独立告警
```

### 字段说明

#### data_list[] — ★ V6: 纯轨迹帧（不再包含 alarm）

| 字段 | 类型 | 说明 |
|------|------|------|
| `device_sn` | string | 无人机编号 `UAV-0001` ~ `UAV-0300` |
| `longitude` | number | 经度（度） |
| `latitude` | number | 纬度（度） |
| `height` | number | 海拔高度（米） |
| `speed` | number | 飞行速度（m/s） |
| `legality` | number | 1=合法, 2=未知, 3=不合法 |
| `timems` | number | Unix 毫秒时间戳 |

#### alarms[] — ★ V6: 独立告警实体（时段事件）

| 字段 | 类型 | 说明 |
|------|------|------|
| `alarmId` | string | 告警唯一标识 `ALARM-00001` ~ `ALARM-03000` |
| `droneId` | string | 产生告警的无人机编号 |
| `alarmType` | string | 告警类型（12种，见 constants.js） |
| `alarmLevel` | string | `严重告警` \| `一般告警` |
| `alarmTypeField` | string | 告警分类: `boundary`/`conflict`/`deviation`/`signal_loss`/`fault`/`illegal`/… |
| `startTime` | number | 告警起始秒数 |
| `endTime` | number | 告警结束秒数 |
| `beginTime` | string | 格式化起始时间 `"2026-05-21 08:02:00"` |
| `reason` | string | 告警原因描述 |
| `nowLatitude` | number | 告警产生时的纬度 |
| `nowLongitude` | number | 告警产生时的经度 |
| `nowHeight` | number | 告警产生时的高度 |

**★ 告警分配策略：**

| 分组依据 | 告警数/架 | 单条持续时间 |
|----------|:--------:|:----------:|
| `seed % 4` | 0~3 条 | 60~360s |

使用确定性种子 `(index * 13 + 7)`，同一无人机在任何窗口中查询结果一致。**同一无人机可以同时存在多条告警**。

## 6. ★ V6 时间跳转告警 diff 机制

```
用户拖拽时间轴从 T1=300s 跳到 T2=1800s
    │
    ├── 跳转前活跃告警集合 A = getActiveAlarms(300)
    │     → { ALARM-00005, ALARM-00012, ALARM-00033, ... }
    │
    ├── 加载新包 packet/30
    │
    ├── 跳转后活跃告警集合 B = getActiveAlarms(1800)
    │     → { ALARM-00012, ALARM-00104, ALARM-00201, ... }
    │
    └── diff:
          started = B - A  → 新产生的告警 ✨
          ended   = A - B  → 已结束的告警 🏁
          active  = A ∩ B  → 持续中的告警
```

前端通过 `droneSim.diffAlarmsAfterJump(prevAlarmIds, newTimeSec)` 调用。

## 8. 数据加载时序

```
页面初始化
    │
    ├── (并行) GET /api/airspace/data        ← 永久空域、永久航路、热力图、网格
    ├── (并行) GET /api/drone/meta           ← 元数据（仅展示用）
    │
    └── (以上完成后) GET /api/drone/packet/0 ← 第 0 分钟包
            │                                  （纯轨迹 + 独立告警 + 时效数据 + 飞行计划）
            ├── 用户点击播放 ▶ → 按需加载后续包
            │
            └── 用户拖拽时间轴 → seekToTime → 加载目标包
                    └── 告警 diff: 检测跳越区间的新增/结束告警
```
